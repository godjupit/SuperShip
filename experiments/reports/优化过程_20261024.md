# 优化过程

## 当前最快方案

544 输入、FP16、CUDA Graph，融合 **99 对 Conv-BN**，main 已默认启用。

| 指标 | 结果 |
| --- | ---: |
| 合并后三轮耗时 | 330.8 / 324.6 / 346.3 ms |
| 中位数 | **330.8 ms** |
| 验证集 AP50 | **0.9057** |
| 最近正式接受成绩 | **340.3 ms** |

10 对对照中，融合中位数缩短 **4.76%**，8 对更快，仍有波动。隐藏集精度未测。

## 瓶颈判断

以下仍为未融合对照；硬件指标取每类首个匹配调用，不代表全部形状。

| 类型 | 实测现象 | 判断与方向 |
| --- | --- | --- |
| Compute Bound | 卷积样本 SM 吞吐 24.38%，占用率 14.50% | 未见算力饱和，先查并行度和依赖 |
| Memory Bound | concat 样本 DRAM 吞吐 82.70%，L2 吞吐 88.81% | 访存受限，优先减少拼接和中间读写 |
| Launch Bound | 70.30% 的内核短于 5 μs；25 次 Graph replay | 小内核多，可尝试融合；启动瓶颈未确认 |
| Synchronization Bound | CPU 等待 event 累计 136.6 ms | 主要是等 GPU，尚无多余同步的直接证据 |
| CPU / I/O Bound | 历史输入等待 49.3 ms；本次首末 GPU 活动间覆盖率 98.51% | 稳态供给较充分，继续检查首批读取 |

优先：重测融合后的热点，再减少类型转换、拷贝和 concat。
