# 推理优化追加实验（2026-10-22）

本轮新增 **22 组配置、66 次独立参考集 worker 计时**，另对 7 个候选运行完整 1,030 张验证集。当前推荐已改为 `benchmark_optimized.sh` 默认参数：**544 输入、三层完整解码器、半尺寸 JPEG 解码、FP16、CUDA Graph、OpenCV cvtColor 直接写入锁页缓冲区、异步结果回传、cuDNN 算法搜索**。

最终三轮：**0.375216336 / 0.381344812 / 0.379818620 秒**，中位数 **0.379818620 秒**。同机同协议基线复测中位数 0.475669439 秒，本轮耗时减少 **20.15%**，吞吐约 **1.252×**。原历史最快为 0.476629654 秒，较之减少 20.31%。

两组独立三轮确认：旧方案中位数 0.477079557 / 0.475669439 秒，新方案 0.380510271 / 0.379818620 秒。全部逐轮结果保留，没有拼接日志。当前服务器已接受最终完整三轮日志（`timing parsed only`）；隐藏集 AP50 **未测**，RTX 3090 性能 **未测**，结果均来自单张 RTX 4090。

## 精度与候选选择

最终方案参考集三轮 AP50=[0.7819, 0.7817, 0.7814]，完整验证集 AP50=0.9054。相对本次未优化基线，参考集门槛为 `0.7935 × 0.98 = 0.77763`，验证集门槛为 `0.9170 × 0.98 = 0.89866`。两个划分分别检查，不能代表隐藏集保证。此前最快方案验证集为 0.9101；新的输入缩小方案有一定精度损失。

512 输入虽然只有 0.362355174 秒，验证集 AP50=0.8960，低于门槛，**排除**。单层解码器 + 阈值 0.04 虽然参考集通过，验证集只有 0.8926，同样排除。576 输入结合提前结束解码器时参考集不通过，也未推荐。两层解码器 + 阈值 0.04 的验证集通过，但速度慢于最终完整三层方案。

保留本轮更大精度余量方案：640 输入、其余新选项相同，三轮中位数 0.447681871 秒，验证集 AP50=0.9100。复现：`INPUT_SIZE=640 bash benchmark_optimized.sh`。

## 为什么有效

1. **减少模型输入计算**：640→544 将像素数降为原来的 72.25%，减少骨干、特征图和编码器的计算及内存流量。原图尺寸仍用于最终坐标还原，全部图像都实际推理。计算量并非所有算子都按像素同比缩减，故这里用实测端到端时间判断。640 组合方案约 0.448 秒，544 最终约 0.380 秒，输入缩小是主要新增收益，但会改变模型预测。
2. **减少 CPU 图像转换开销**：旧代码通过 NumPy 的负步长通道视图做 RGB 拷贝；新代码用 OpenCV `cvtColor(..., dst=destination)` 写入预分配锁页缓冲区。基线 0.4771 秒，单独切换约 0.4593 秒。JPEG 半尺寸解码以及各测试输入尺寸的像素逐值一致检查通过。API 依据：[OpenCV 颜色转换](https://docs.opencv.org/4.x/d8/d01/group__imgproc__color__conversions.html)。
3. **重叠 GPU 与 CPU 后处理**：将结果异步复制到有界的锁页输出环形缓冲区，先发起下一批 GPU 工作，再格式化上一批结果。CUDA event 保证 CPU 读取完成后的回传数据，也保证静态 Graph 输出在下次复用前复制完成。单独开启异步回传约 0.4590 秒，两者结合约 0.4560 秒，收益存在重叠，不能直接相加。实现依据：[PyTorch 锁页内存和非阻塞传输](https://docs.pytorch.org/tutorials/intermediate/pinmem_nonblock.html)。
4. **固定尺寸算法选择**：cuDNN benchmark 在初始化的合成输入预热阶段搜索卷积算法，640 组合方案由约 0.4560 降至 0.4477 秒。它可能引入轻微数值差异，因此实际评分每一轮，而不假设预测逐字节相同。[PyTorch 性能调优指南](https://docs.pytorch.org/tutorials/recipes/recipes/tuning_guide.html)提供相应固定尺寸优化和减少同步的依据。

上述因果解释基于代码路径和消融对照，没有把 GPU kernel profile 当作已测结果。cvtColor、异步输出以及组合方案在关闭 cuDNN 搜索、保持 640 输入时，与基线生成的预测 JSON SHA256 完全一致。更改输入尺寸、cuDNN 算法、解码层数后的预测则重新核对精度。

## 文献方向与未采用方案

[RT-DETR（CVPR 2024）](https://arxiv.org/abs/2304.08069)提出通过改变解码层数调节推理速度。本轮在当前 D-FINE/RT-DETRv4 权重上实测 1/2 层推理，精度和输出成本使其没有胜过完整三层的最终方案。这是对论文方向的具体实验，不能将论文中的无重训练调速结论直接当作本赛题精度保证。

[RT-DETRv4](https://arxiv.org/abs/2510.25257)使用视觉基础模型蒸馏改善轻量检测器，属于需要训练的路线；本轮保留官方权重，没有声称完成新蒸馏或 INT8 校准。更大 batch、减少读取线程、原地 resize/cvtColor、完整 JPEG 解码和不同输入尺寸的成功、无收益及失败结果全部见下表。

## 复现和边界

```bash
cd /home/ubuntu/SuperShip-optimize
PYTHON_BIN=/home/ubuntu/.cache/supership-venv/bin/python bash benchmark_optimized.sh
# 更大精度余量：
PYTHON_BIN=/home/ubuntu/.cache/supership-venv/bin/python INPUT_SIZE=640 bash benchmark_optimized.sh
```

默认配置不裁减解码层，保持全部训练权重。`OPENCV_COPY_MODE=strided`、`ASYNC_OUTPUT=0`、`CUDNN_BENCHMARK=0` 和 `INPUT_SIZE=640` 可恢复本轮控制条件。输入边长必须为 320–1280 范围内的 32 倍数。更改尺寸会在初始化阶段重建位置编码和锚点，先严格加载权重，不丢弃训练参数。
