## 实际采用的优化

1. 初始化时启动读取线程，分配锁页缓冲区；READY 后才读取元数据和图像。三组缓冲区限制预取内存，同时重叠读取、解码和推理。
2. OpenCV 使用 JPEG 的 1/2 缩小解码，再缩放到 640×640；检测框仍按原图尺寸还原。该做法会改变图像细节，单独进行了参考集和验证集精度检查。
3. 使用同一 RT-DETRv4 模型结构和官方权重；采用 channels-last、FP16，以及捕获输入转换、模型前向和 GPU 后处理的 CUDA Graph。仅用合成图像预热和捕获。
4. 整批回传结果，使用 NumPy 向量化结果处理；过滤置信度低于0.05的检测，减少结果组装和序列化。所有输入图像均实际完成推理。
5. 使用 orjson 一次性序列化；等待读取线程结束、同步全部 GPU 工作，完成文件 flush/fsync 并关闭文件后，直接结束进程，减少 Python/CUDA 析构开销。

## 未采用或需要保留对照的方向

- 单独使用 FP16、增大 batch、增加线程数、模型 deploy 转换没有稳定的额外收益；应按实测组合选择。
- nvJPEG GPU 解码及分组缩放约1.87–1.97秒，慢于 CPU OpenCV 多线程路线，保留实现和实测记录。
- 阈值0.1虽然较快，但参考集 AP50=0.7753，低于本次参考基线98%的0.77763，未正式提交。
- 原始完整图像、低阈值方案提供更大的精度余量，可通过环境变量切换。

